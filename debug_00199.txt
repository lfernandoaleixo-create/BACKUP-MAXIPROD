BUG: Product 00199 (Casca Verde) shows pedidosCx=7 but should be 32

ROOT CAUSE:
- Pedido 1594: qty=26, unit='un', fatorConversao=1
- Pedido 1587: qty=1, unit='CX', fatorConversao=5000
- Pedido 1583: qty=5, unit='CX', fatorConversao=5000

In stockProcessor.ts line 588: totalCx += qtyCx (adds 26+1+5 = 32, CORRECT)
In stockProcessor.ts line 597-601: totalUn calculation
  - For CX orders (fator=5000): totalUn += 5000 * qty = 25000 + 5000 = 30000
  - For un order (fator=1): totalUn += 1 * 26 = 26
  - Total: totalUn = 30026

Then at line 830-834: pedidosCxVal = Math.ceil(pedidosUn / unitsPerBox) = Math.ceil(30026/5000) = 7

THE FIX:
The issue is that fatorConversao=1 with unidadeMedidaCodigo='un' means 1 selling unit = 1 stock unit.
But the stock unit IS the CX (box) for this product. So 26 un = 26 CX = 26*5000 = 130000 individual units.

Fix option 1: In the totalUn calculation, when fatorConversao <= 1 (or =1), 
check if extractUnitsPerBox gives a higher value from description. If so, use that.

Fix option 2: Use totalCx directly for pedidosCxVal instead of pedidosUn/unitsPerBox.
This is simpler but might break other products.

BEST FIX: In line 597-601, when fator=1 and the description has a higher unitsPerBox,
use the description's unitsPerBox instead. This handles the case where the order was placed
in the product's base unit (CX) but the unidadeMedidaCodigo says 'un'.
